# 빈자리의 혼례 · 실제 웹캠 C

승인된 두 의례물형 캐릭터 시트로 만든 Chrome 카메라 전시 실행본입니다. 기존 Godot/Python 프로젝트와 별도입니다. HTML/CSS/JavaScript와 로컬 MediaPipe Face/Pose를 사용합니다.

## 실행

Windows PC에 Chrome과 **Node.js 22 이상**을 한 번 설치하세요. 배포 폴더 전체를 복사한 뒤 `START_EXHIBITION.cmd`를 더블클릭합니다. npm 설치 없이 실행됩니다. Chrome에서 `http://localhost:4173/`가 열립니다. 주소가 열리지 않으면 `http://127.0.0.1:4173/`를 입력하세요. 서버 창은 전시 중 열어 둡니다. 종료는 서버 창에서 Ctrl+C입니다.

1. **카메라 시작**을 누르고 Chrome의 카메라 권한을 허용합니다. 실제 프레임이 도착해야 ‘카메라 연결됨’이 표시됩니다.
2. 설정에서 사용할 카메라와 해상도를 선택합니다. 선택을 바꾸면 ‘저장하고 카메라 다시 연결’을 누릅니다.
3. **화면에서 의자 영역 그리기**를 눌러 관객의 엉덩이가 놓이는 부분을 드래그합니다. 좌우 반전 영상에 맞춘 영역입니다.
4. 어깨·엉덩이·무릎·발목이 보이는 각도를 권장합니다. 무릎이 안 보이면 실제 착석 자세를 2초간 저장하고 ‘무릎이 안 보일 때 저장된 착석 기준 허용’을 켭니다. 이 모드는 서 있는 사람과 혼동할 수 있어 현장에서 반드시 비교 시험하세요.
5. 설정을 닫으면 자동 감지가 기본으로 작동합니다. 같은 자리에서 자세를 약 1.8초 유지하면 시작합니다. 어두운 화면에서는 관객 앞쪽에 은은한 조명이 필요합니다.

**F** 전체화면 / **R** 초기화 / **D** 감지·성능 정보 / **H** 운영 표시 숨김 / **Space** 비상 수동 연출. 수동은 화면에 표시되며 자동 착석 시험으로 기록되지 않습니다. 연출 종료 후 계속 앉아 있으면 반복하지 않고 자리가 비워진 다음 재무장합니다.

## 진행

관객 대기 → 접근 감지 → 착석 확인 → 대기 → 양옆 등장 → 1.5초 정지 → 손각시 가리개 내림 → 0.8초 뒤 몽달 가리개 내림 → 응시 → 퇴장 → 투명 상태 초기화. 관객 이탈·입력 유실에도 유예 후 퇴장합니다. 장면의 위치·크기·등장·가리개 변화는 경과 시간으로 계산합니다.

## 현재 시각적 한계

두 원본 시트의 정면 전신을 그대로 잘라 투명 WebP로 만들었습니다. 두 전신 합계 약 275KB입니다. 얼굴이나 의상을 새로 그리지 않았습니다.

**가리개는 레이어 시안입니다.** 원본에는 가리개를 두 손으로 들거나 내리는 자세가 없습니다. 현재 손은 원본 자세 그대로이며 종이 레이어만 이동합니다. 미세한 고개 변화는 제한적인 2D 변형이며 실제 눈동자 올림·자연스러운 팔 동작을 완성한 상태가 아닙니다. 해당 구간의 승인된 사전 제작 영상이 필요합니다. 이 부분까지 최종 전시 품질로 완료했다고 보지 않습니다.

설정에서 투명 WebM을 임시 연결해 시험할 수 있습니다. 지속 적용은 `public/assets/characters/manifest.json`의 각 캐릭터 `revealVideo`에 로컬 경로를 지정합니다. 동일 전신·얼굴·의상·크기와 알파를 유지하고 첫 프레임이 가리개를 든 자세, 마지막 프레임이 내린 자세여야 합니다. 시작/끝 자세, 손가락, 얼굴 일관성을 실제 재생으로 검수해야 합니다. 기존 이미지와 영상 첫 프레임이 다르면 전환이 튈 수 있습니다.

## 오프라인·개인정보

배포본에는 `public/models`와 `public/vendor`가 포함됩니다. 실행 중 유료 API, CDN, 생성 AI, 인터넷 연결을 요구하지 않습니다. Node는 이 PC의 loopback 주소에서 정적 파일만 제공합니다. 다른 PC에서는 각자 시작 스크립트를 실행하세요. 카메라·얼굴·관절 영상은 업로드하거나 녹화하지 않습니다. 로그 내보내기는 수치·상태·실제 카메라 설정만 포함합니다. 브라우저에 저장한 설정은 PC마다 따로 보정해야 합니다.

## 구조와 재현

- `public/lib/camera.mjs`: 실제 입력과 프레임 도착 확인
- `public/vision-worker.js`: 별도 Worker에서 Pose 12회/초 목표, Face 절반 주기
- `public/lib/seat.mjs`: ROI·다리 굽힘/저장 자세·안정성·착석 유지
- `public/lib/interaction.mjs`: 상태 전환, 이탈 유예, 회차 재무장
- `public/lib/scene.mjs`: 승인 에셋과 독립적인 화면 애니메이션
- `sources/approved`: 승인된 원본 2개, `licenses`: 출처·버전·해시
- `docs/PROGRESS.md`: 확인 결과와 미검증 항목

개발 재현은 `npm ci`, `npm run setup`, `npm run assets`, `npm test`, `npm run verify` 순서입니다. 처음 리소스를 준비할 때만 인터넷이 필요합니다. `npm run package`는 node_modules 없이 오프라인 리소스를 포함한 배포 폴더를 만듭니다. 이미 받은 배포본은 이 준비 과정이 필요 없습니다. 비공개 저장소는 https://github.com/jingeosal-ui/empty-seat-wedding-web 이며 연결 기록은 `docs/GITHUB.md`를 참조하세요. 실제 관객 시험 순서와 기록표는 `docs/현장_카메라_시험안내.md`에 있습니다.

## 현장 검증

`http://localhost:4173/diagnostics.html`은 로컬 모델 실행을 검은 프레임으로 확인합니다. 사람·착석 정확도 시험과 다릅니다. 실제 카메라에서 착석·일어섬·잠깐 통과·빈 의자·어두운 의상·역광을 각각 반복하고 D 화면의 인식 이유와 결과 나이를 확인하세요. AI 결과가 오래되거나 카메라가 멈추면 착석을 진행하지 않습니다. 웹캠 출력 목표 30FPS 이상, 화면 목표 60FPS이며 실제 성능은 D 화면과 ‘검증 기록 저장’으로 측정합니다. 목표값을 실측 달성으로 읽지 마세요.
